# Frontend Support in Cali

Cali now supports automatic frontend scaffolding with TypeScript client generation from your gRPC proto files!

## Quick Start

### Create a New Project with Frontend

```bash
cali new my-app --frontend
cd my-app
```

This creates:
- Standard Cali backend (Rust + tonic gRPC)
- SvelteKit frontend with Connect-Web
- Auto-generation script for TypeScript clients

### Generate TypeScript Clients

After modifying your proto files:

```bash
# Generate Rust controllers (backend)
cali generate controllers

# Generate TypeScript clients (frontend)
cali generate frontend
# Or from frontend directory:
cd frontend && npm run generate
```

## How It Works

### 1. Proto Files → Dual Code Generation

```
interface/grpc/services/accounts.proto
  ↓
  ├─→ [Cali] → web/src/controllers/accounts.rs (Rust)
  └─→ [Connect-Web] → frontend/src/lib/generated/accounts_connect.ts (TypeScript)
```

### 2. Type-Safe Client Usage in Svelte

```typescript
import { createPromiseClient } from '@bufbuild/connect-web';
import { Accounts } from '$lib/generated/accounts_connect';
import { transport } from '$lib/api/client';

const client = createPromiseClient(Accounts, transport);

// Fully typed!
const response = await client.createAccount({
  name: "John",
  email: "john@example.com",
  password: "secret"
});
```

### 3. Single Source of Truth

Write proto files once, get:
- ✅ Rust gRPC server controllers
- ✅ TypeScript browser clients
- ✅ Perfect type safety on both sides
- ✅ Auto-completion in your editor

## Frontend Stack

- **SvelteKit**: Modern, fast, excellent DX
- **TypeScript**: Full type safety from protos
- **Connect-Web**: gRPC-Web client library
- **Prettier + ESLint**: Code formatting and linting
- **Vite**: Fast builds and HMR

## Workflow

```bash
# 1. Write your proto files
vim interface/grpc/services/my_service.proto

# 2. Generate backend
cali generate controllers

# 3. Generate frontend
cali generate frontend

# 4. Run backend (terminal 1)
cd web && cargo run

# 5. Run frontend (terminal 2)
cd frontend && npm run dev

# Both are now in sync! 🎉
```

## Backend Setup for Web Clients

Your tonic server needs gRPC-Web support. Add to `web/Cargo.toml`:

```toml
tonic-web = "0.9.2"
```

Then wrap your services (see `web/README_TONIC_WEB.md` for details):

```rust
use tonic_web::GrpcWebLayer;

let server = Server::builder()
    .layer(GrpcWebLayer::new())  // Add this
    .add_service(YourService::new(...))
```

Or use an Envoy proxy (recommended for production).

## Desktop App Support (Optional)

Convert your SvelteKit app to a native desktop app with **Tauri**:

```bash
cd frontend
cargo install tauri-cli
cargo tauri init
cargo tauri dev
```

The same gRPC clients work in both web and desktop! See `frontend/TAURI_SETUP.md`.

## Mobile Support (Future)

Use **Capacitor** for iOS/Android:

```bash
npm install @capacitor/core @capacitor/cli
npx cap init
npx cap add ios
npx cap add android
```

Same clients, same code—runs everywhere!

## Project Structure

```
my-app/
├── interface/grpc/services/     # Proto files (source of truth)
├── web/                         # Rust gRPC backend
│   ├── src/controllers/        # Generated by: cali generate controllers
│   └── Cargo.toml
├── frontend/                    # SvelteKit app
│   ├── src/lib/generated/      # Generated by: cali generate frontend
│   ├── scripts/generate-clients.sh
│   └── package.json
└── Cargo.toml
```

## Benefits

1. **DRY**: Write APIs once in proto files
2. **Type Safety**: End-to-end types from proto → Rust + TypeScript
3. **Fast Iteration**: Change proto → regenerate → instant feedback
4. **Consistent**: Backend and frontend can't drift apart
5. **Modern**: Best-in-class tools for both ecosystems

## Migrating Existing Projects

Add frontend to an existing Cali project:

```bash
# In your project root
cd my-existing-cali-project

# Create frontend (manual, or wait for `cali add frontend`)
# For now, copy from a new project:
cali new temp-project --frontend
cp -r temp-project/frontend ./
rm -rf temp-project

# Generate clients
cd frontend && npm run generate
```
